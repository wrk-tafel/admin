# ADR-0009: Documents rendered server-side — XSL-FO/Apache FOP for PDF, Commons CSV for exports

**Status:** accepted · **Recorded:** 2026-08-09

## Context

The system produces printed and emailed artefacts that are handed to people or filed:

- the household master-data sheet and the ID card (with an embedded QR code and the Tafel logo),
- the per-distribution daily report PDF, emailed when a distribution closes,
- the household list for a distribution,
- a set of "TOeT" CSV analysis exports, emailed alongside the daily report,
- an ad-hoc CSV export from the statistics screen.

Two properties matter. These documents are *records*: a daily report regenerated later must look the
way it looked then. And several of them are produced with no browser in the loop at all — the daily
report is generated by an event listener after a distribution closes, and emailed.

## Decision

**All documents are rendered on the server. PDFs go through XSL-FO templates rendered by Apache FOP;
CSVs go through one Commons CSV utility.**

PDF pipeline, shared by every PDF in the app via `common/pdf/PDFService`:

1. A Kotlin data model (e.g. `DailyReportPdfModel`, annotated `@JsonRootName("data")` to match the
   template's root match) is serialized to XML with a Jackson `XmlMapper`.
2. That XML is transformed by the XSL stylesheet at
   `backend/src/main/resources/pdf-templates/<area>/...xsl`, with `<xsl:include>`s resolved from the
   classpath by a custom `ClasspathResourceURIResolver`.
3. The resulting XSL-FO is rendered to PDF bytes by Apache FOP. Liberation Sans fonts are extracted
   from the classpath to a temp directory at factory-build time, because FOP needs real filesystem
   paths for font registration.

CSV: every exporter builds a plain `List<List<String>>` (header rows included) and hands it to
`common/csv/CsvUtil.writeRowsToByteArray`, which uses Apache Commons CSV with `;` as the delimiter —
matching what Austrian/German Excel expects — and UTF-8.

Layout changes are XSL changes. The Kotlin side only changes when the *data* changes, since the XML
shape is derived from the model's field names.

## Consequences

- Documents are reproducible and independent of any client. The same code path serves a browser
  download and an emailed attachment, and there is no headless-browser process to install, sandbox
  or keep alive.
- Report content is a **historical snapshot**, not a live join: the daily report reads shelter data
  off `DistributionStatisticEntity`, and ages are computed against `distribution.startedAt` rather
  than the clock. Renaming a shelter or letting a birthday pass does not rewrite past reports. This
  is a deliberate property of the design, not an accident of caching.
- **XSL-FO is a niche skill.** Editing a layout means reading XSLT and FO, and the feedback loop is
  "render the PDF and look at it" rather than a browser devtools inspector. That is the main cost of
  this decision and it is real.
- Adding a mailed CSV export is one `@Component` implementing `StatisticExporter`; Spring collects
  them and `StatisticExportService` picks the new one up with no other wiring.
- The `;` delimiter is a locale decision baked into the utility. Anything consuming these files
  programmatically has to know that.
- Two unrelated CSV paths live in `reporting` — the mailed `statisticexporter/*` files and the
  statistics screen's `/api/statistics/generate-csv` — with different SQL and different row shapes.
  "The CSV export" is ambiguous; both exist.

## Alternatives considered

**HTML templates rendered to PDF by a headless browser (Puppeteer/Playwright, wkhtmltopdf).** The
nicer authoring experience, and rejected on operations: it means shipping a browser inside the
container, keeping it patched, and adding a process the JVM has to supervise — for documents
generated a handful of times per distribution day.

**A programmatic PDF library (iText/PDFBox) building layout in Kotlin.** Rejected: page layout,
pagination and table breaking become imperative code, and every layout tweak becomes a backend
change plus a redeploy instead of a stylesheet edit.

**Generating documents in the frontend.** Rejected outright: the daily report has no browser
involved — it is produced by a backend event listener and emailed.

**Hand-rolled CSV writing.** Rejected: quoting and escaping are exactly the details that a
well-tested library gets right and hand-rolled string joining gets wrong on the first field
containing a semicolon.
